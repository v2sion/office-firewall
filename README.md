# OFFICE FIREWALL

> 직장에서 받은 애매한 메시지를 넣으면, AI가 그 안의 실제 요구와 빠진 알맹이를 진단하고,
> 원하는 톤으로 답장을 만들어 주는 도구.

원티드 AI CHAMPIONSHIP 2026 · 팀 **90od**

## 설계 원칙

| # | 원칙 | 구현 위치 |
|---|---|---|
| 1 | **AI는 추출, 판정은 규칙** — AI는 점수를 만들지 않는다 | `src/lib/score.js` 가 점수의 단일 출처. `api/_lib/prompt.js` 는 `riskScore` 생성을 금지한다 |
| 2 | **원문을 AI에 먼저 보내지 않는다** — 브라우저 선-마스킹 | `src/lib/mask.js`. 토큰 맵은 `src/main.js` 의 지역 변수에만 존재하며 저장·전송하지 않는다 |
| 3 | **진단 먼저, 답장 나중** — X-Ray가 위, 답장이 아래 | `index.html` 결과 패널 순서 |

서버는 마스킹되지 않은 전화번호·이메일이 섞인 요청을 `RAW_PII_DETECTED` 로 거부한다.
로그에는 본문을 남기지 않고 길이·지연시간·토큰 사용량·점수만 기록한다.

## 데이터 계약 — `POST /api/analyze`

**Request**

```json
{
  "maskedText": "{{PERSON_1}}님 주말에 미안한데, ...",
  "context": {
    "job": "기획·PM/PO", "level": "주니어", "counterpart": "직속상사",
    "goal": "칼차단", "tone": "보통맛", "hiddenContext": "가족 행사로 외지에 있음"
  }
}
```

**Response**

```json
{
  "xray": {
    "subtext": "...", "powerAsymmetry": 4,
    "urgencyType": "주말 침범", "ambiguityType": "범위 불명",
    "aiSlopScore": 0, "clicheHits": ["시간 날 때", "가볍게", "급한 건 아니"],
    "sentenceCount": 3, "hasNumbers": false, "hasDeadline": false, "avoidsDecision": true,
    "aiReported": { "...": "AI가 보고한 원본 (검증용)" }
  },
  "replies": [{ "label": "목적 맞춤형 정밀 방어", "text": "{{PERSON_1}}님, ..." }],
  "risk": { "score": 92, "level": "red", "label": "즉각 승인 금지", "header": "🚨 고위험 독박 경보", "breakdown": [] },
  "usage": { "input_tokens": 0, "output_tokens": 0 },
  "meta": { "mode": "mock", "model": "mock", "latencyMs": 3 }
}
```

- **AI는 `riskScore` 를 반환하지 않는다.** `risk` 는 서버의 룰엔진이 계산한 값이고,
  클라이언트도 같은 모듈(`src/lib/score.js`)로 재현할 수 있다.
- 클리셰·수치·기한·의사결정 회피는 **규칙 계산값을 채택**하고, AI가 보고한 값은
  `xray.aiReported` 에 남겨 대조할 수 있게 둔다. AI가 지어낸 클리셰는 원문 대조로 걸러진다.
- 답장 텍스트에는 마스킹 토큰이 그대로 들어 있고, 브라우저가 렌더링 직전에 역치환한다.

## 룰엔진

```
Social Risk Index = 권력 비대칭(0~40) + 시간적 긴급도(0~20) + 요구 모호성(0~20) + 알맹이 결여율(0~20)
  권력 비대칭 = powerAsymmetry(1~5) × 8
  시간적 긴급도 = urgencyType ≠ "없음" → 20
  요구 모호성 = ambiguityType ≠ "없음" → 20
  알맹이 결여율 = (클리셰 밀도 + 수치·기한 부재 + 의사결정 회피) / 3 × 20
```

**정상 업무 가드**: 긴급도·모호성이 모두 "없음" 이고 결여율이 0이면 점수는 Green 상한(20)을
넘지 않는다. 과잉 방어는 제품 신뢰를 깎기 때문이다 (골든 ⑤ 대조군 검증 조건).

한글 사전 매칭은 NFD(자모 분해) 기준이다. `"아니"` 는 `"아닙니다"` 의 부분문자열이 아니라서
음절 그대로 비교하면 사전이 헛돈다.

### 입력 흐름 — 상황 카드는 ③ 받은 메시지만 채운다

`② 구체적인 상황` 카드는 **③ 받은 메시지 하나만** 채운다. 처음엔 맥락 매트릭스·숨은
속사정·목적·완곡도까지 전부 덮어썼는데, 두 가지 문제가 있었다:

- **① 맥락 매트릭스(내 직군·연차)는 "나"에 대한 정보**라 상황과 무관하게 유지돼야 하는데,
  카드를 누르는 순간 방금 ①에서 설정한 값이 사라졌다 — 순서(①→②)와 모순되는 동작이었다.
- **⑤ 방어 목적·⑥ 완곡도는 사용자가 메시지를 읽고 스스로 정해야 할 몫**인데 카드가
  미리 정해버리면 "상황 예시"가 아니라 "데모 세트 통째로 불러오기"가 된다.

지금은 카드를 눌러도 상대방과의 관계·숨은 속사정·목적·완곡도는 사용자가 지금 설정해 둔
값 그대로 유지된다. 결과로 바로 넘어가지도 않는다 — `⑦ 실행` 버튼을 직접 눌러야 한다.

> **프리셋 캐싱과의 트레이드오프**: 아래 "프리셋 0초 캐싱"은 폼 전체(메시지 + 숨은 속사정 +
> 맥락 매트릭스 + 목적 + 완곡도)가 골든 프리셋 원본과 완전히 같을 때만 히트한다. 상황 카드가
> 메시지만 채우는 지금은 카드 클릭만으로 캐시가 히트하지 않는다(숨은 속사정 등 나머지 필드가
> 비어 있거나 사용자 값과 다르기 때문). 캐시 로직 자체는 그대로 살아 있고 테스트도 통과하지만,
> 실제로는 사용자가 나머지 필드까지 우연히 골든 값과 똑같이 맞췄을 때만 작동한다 — 대신
> 캐시가 빠지면 로컬 룰엔진(MOCK/LOCAL)이 즉시 대신하므로 체감 속도·안정성 차이는 거의 없다
> (실측 수 ms 수준). 이 트레이드오프를 감수할지, 메시지 외 필드는 그대로 두되 골든 값과
> 무관하게 "핵심 추출값만 캐시 재사용 + 답장은 사용자가 고른 목적/톤으로 즉석 생성"하는
> 하이브리드 캐싱으로 바꿀지는 다음 결정 사항으로 남겨둔다.

## Sprint 1 — 완곡도 · 결여율 · 프리셋 캐싱 · 마스킹 무결성

### 1) 프리셋 0초 캐싱 (가이드 §9)

폼 전체(메시지 + 숨은 속사정 + 맥락 매트릭스 + 목적 + 완곡도)가 골든 프리셋 원본과
**완전히 같을 때만** `src/data/presets/<id>.json` 을 그대로 렌더링한다 — 네트워크 호출도,
룰엔진 재계산도 없다. 하나라도 다르면 즉시 캐시를 포기하고 정상 분석 경로
(서버 → 실패 시 로컬 룰엔진)로 넘어간다.

> ② 구체적인 상황 카드가 메시지만 채우도록 바뀌면서(아래 "입력 흐름" 참고), 카드 클릭만으로는
> 더 이상 캐시가 자동으로 히트하지 않는다 — 로직·테스트는 그대로 유효하지만 실제 발동 조건이
> 좁아졌다.

```
node scripts/gen-presets.mjs   # buildMockAnalysis() 출력을 스냅샷으로 저장/갱신
```

`mock.js` 의 문구를 바꾸고 이 스크립트를 다시 안 돌리면 캐시가 조용히 낡는다 —
`test/presets.test.js` 가 캐시와 최신 `mock.js` 출력을 `deepEqual` 로 대조해 드리프트를 잡는다.

Playwright로 실측 (네트워크 요청 가로채기):

| 시나리오 | API 호출 | 모드 배지 | 비고 |
|---|---|---|---|
| 프리셋 그대로 실행 | **0회** | `PRESET · $0` | 캐시 히트, 실측 2ms |
| 메시지를 한 글자라도 수정 | 1회 시도 | `MOCK` | 캐시 미스 → 정상 경로 |

### 2) 완곡도 3단계 — 실제 차등 생성 확인

세 가지 답장 슬롯(목적 맞춤형 정밀 방어 / 선제적 아젠다 요구 / 속마음 분노 세탁 버전)
전부 톤(순한맛·보통맛·매운맛)마다 다른 문장을 낸다. 초기 구현은 "속마음 분노 세탁"이
순한맛·보통맛에서 같은 문구를 썼는데(2단계밖에 차등이 없었음), Sprint 1에서
순한맛 전용 문구를 추가해 3단계 전부 실제로 달라지게 했다.

`test/tone.test.js` 가 목적(4) × 톤(3) = 12개 조합이 전부 서로 다른 문자열인지,
매운맛에 쿠션어("괜찮으", "편하게", "혹시"…)가 섞이지 않는지 검증한다.

### 3) 알맹이 결여율 — 컷 우선순위 완성 (가이드 §11)

`src/lib/score.js` 의 `SUBSTANCE_METRICS` 플래그로 3중 → 2중 결여율을 즉시 전환할 수 있다.
시간이 부족하면 가이드 §11 1순위대로 `avoidsDecision` 부터 끈다:

```js
export const SUBSTANCE_METRICS = {
  clicheDensity: true,
  missingSpec: true,
  avoidsDecision: false, // ← 1순위 컷: 의사결정 회피율 제거
};
```

`test/score.test.js` 가 이 플래그를 껐을 때 결여율이 실제로 낮아지는지(3중 2/3 → 2중 1/2)
확인한다.

### 4) 마스킹/역치환 무결성 — 발견한 우회 경로 수정

재검토 중 `④ 나의 숨은 속사정` 자유 입력 필드가 마스킹을 거치지 않고 그대로
`context.hiddenContext` 에 담겨 서버로 전송되고 있었다(설계원칙 1.2 위반 소지). 수정 내용:

- `src/lib/mask.js` 의 `maskFields(message, hiddenContext)` 가 두 필드를 한 번에 마스킹하고
  토큰 번호를 공유한다 (같은 사람이 메시지와 속사정에 함께 나오면 같은 `{{PERSON_n}}`).
- 서버 가드(`RAW_PII_DETECTED`)가 `context.hiddenContext` 도 함께 검사한다.
- "전송될 내용 확인" 미리보기가 숨은 속사정의 마스킹 결과도 함께 보여준다.

Playwright로 실제 네트워크 요청 바디를 가로채 원문(이름·전화번호)이 전혀 포함되지
않음을 확인했다.
