# 새 프로젝트 시작 키트

OFFICE FIREWALL(원티드 AI 챌린지 2026)을 끝까지 만들면서 **실제로 틀렸던
것들**에서 뽑았다. 일반론이 아니라 사건에서 나온 것만 담았다.

이 폴더를 통째로 새 저장소에 복사하고, 그 안의 파일을 제자리로 옮기면 된다.

```
starter/
├── CLAUDE.md                     → 새 저장소 루트로
└── scripts/verify-template.mjs   → 새 저장소 scripts/ 로
```

---

## 1) `CLAUDE.md` 를 루트에 둔다

Claude Code 가 **세션마다 자동으로 읽는다.** 규칙을 매번 설명하지 않아도
된다는 뜻이고, 이게 이 키트에서 가장 값이 큰 부분이다.

담긴 규칙 다섯 가지 — 각각에 그 규칙을 만든 사건이 붙어 있다.

| | 규칙 | 이걸 만든 사건 |
|---|---|---|
| §1 | 주장하지 말고 잰다 | "단호하게" 고쳤다고 생각했는데 재보니 오히려 길었다 |
| §2 | 검증은 에러를 듣게 한다 | 함수가 저장 안 된 채로 검증이 "통과"했다 |
| §3 | 상태 하나에 주인 하나 | 한 상태를 두 곳에서 쓰다 세 번째 조건에서 깨졌다 |
| §4 | 기본값은 선택이다 | 안 고르면 기본값이 사용자 대신 입장을 정했다 |
| §5 | 서로를 부정하지 않는다 | 같은 화면의 두 산출물이 반대로 말했다 |

`§6` 은 비워 뒀다. 프로젝트 고유 규칙(설계 원칙 · 금지 사항 · 검증 명령 ·
하지 않기로 한 것)을 거기에 이어 쓴다.

## 2) `verify-template.mjs` 를 먼저 둔다

**나중에 만들면 안 만든다.** 프로젝트 초반, 화면이 하나라도 생기면 바로
복사해 두고 측정 항목만 채워 넣는다.

```bash
npm i -D playwright && npx playwright install chromium
node scripts/verify-template.mjs http://localhost:5173
```

```
  모바일    390×844   {"가로스크롤":false}
  노트북   1440×900   {"가로스크롤":false}
  큰 모니터 2560×1440  {"가로스크롤":false}

전부 통과 · 에러 없음
```

종료 코드를 돌려주므로 CI 에 그대로 붙일 수 있다.

**고칠 곳은 두 군데뿐이다.**

- `measure()` — 재고 싶은 것을 **숫자로** 돌려준다. 줄 채움 비율을 재는
  헬퍼가 예시로 들어 있다.
- `setup()` — 측정 전에 화면을 원하는 상태로 만든다(로그인 · 입력 · 실행).

**건드리지 말 것** — 상단의 에러 리스너 세 줄. 이게 이 템플릿의 존재
이유다. 화면이 그려졌다는 건 코드가 멀쩡하다는 뜻이 아니다.

`IGNORE` 목록은 **비워 두는 것이 기본**이다. 외부 폰트·분석 스크립트가 매번
경고를 띄우면 얼마 안 가 경고를 통째로 무시하게 되고, 그게 바로 원래 버그가
살아남은 방식이다. 한 줄 넣을 때마다 "이게 정말 내 코드와 무관한가"를 묻는다.

## 시작 순서

1. **`CLAUDE.md` 를 루트에 둔다.** 규칙이 있어야 지킨다.
2. **`verify-template.mjs` 를 `scripts/` 에 둔다.** 화면이 생기기 전에.
3. **자의적으로 정한 값에 외부 근거를 초반에 붙인다.** 점수·가중치·임계값처럼
   내가 정한 숫자가 있다면, 근거를 찾는 작업은 문서 작업이 아니라 **버그 발견
   작업**이다. 늦게 하면 그만큼 늦게 발견한다.
4. **테스트 코퍼스를 두 벌 이상 계획한다.** 내가 만든 것 하나로는 내 사고의
   한계를 못 넘는다. 한 벌은 반드시 **외부에서** 온 것으로.
5. **폴백·예외 경로를 데모 경로와 같은 기준으로 본다.** 장애·한도 초과 때
   보이는 화면이 결국 누군가가 실제로 보는 화면이다.
6. **제출/납품 런북을 중반에 만든다.** 마감 직전에 만들면 빠진 걸 늦게 안다.
