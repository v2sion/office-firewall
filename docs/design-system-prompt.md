# Claude Design — 디자인 시스템 생성 프롬프트

아래 블록을 그대로 복사해 Claude Design(또는 `/design`)에 붙여넣으면 된다.
**이미 코드에 구현된 값**을 기준으로 작성했으므로, 디자인과 코드가 갈라지지 않는다.
토큰을 바꾸려면 이 문서와 `src/styles.css` 의 `:root` 를 함께 고쳐야 한다.

---

## 복사할 프롬프트

```
Office Firewall 의 디자인 시스템 캔버스를 만들어 주세요.

## 제품 맥락

직장에서 받은 애매한 메시지("시간 될 때 가볍게 한번 봐주세요, 급한 건 아닙니다!")를
넣으면, 그 안의 숨은 요구와 빠진 정보를 진단하고 답장을 만들어 주는 웹 도구입니다.
사용자는 이미 지쳐 있는 직장인이고, 결과 화면 옆에는 무료 심리상담(EAP) 링크가 있습니다.

그래서 톤이 중요합니다:
- 진지하되 우울하지 않게. 사용자를 환자가 아니라 판단의 주체로 대합니다.
- 귀엽게 굴지 않습니다. 위험 지수를 다루는 화면이라 신뢰감이 먼저입니다.
- 유머는 "오피스 방어 영수증"(공유용 카드) 한 곳에만 허용됩니다.

## 이미 확정된 토큰 — 새로 발명하지 말고 이 값을 체계화해 주세요

다크 테마 단일 운영입니다(라이트 테마 없음). 실제 구현된 값입니다:

배경/표면   --bg #0b0f16 · --bg-panel #121824 · --bg-soft #182131 · --line #243047
텍스트      --text #e8edf6 · --text-dim #93a1bb · --text-faint #61708c
브랜드      --accent #4f8cff · --accent-dim #2f5fc2
위험 등급   --green #3ddc97 · --lime #a3d94b · --amber #f2c744 · --orange #f5854e · --red #ff5a5f
라운드      --radius-sm 8px · --radius 12px · --radius-lg 18px
서체        본문/UI: Pretendard  ·  숫자·데이터·브랜드마크: 모노스페이스

## 반드시 지켜야 할 의미 규칙 (이게 이 시스템의 핵심입니다)

**브랜드 색(파랑)과 위험 등급 색(초록~빨강)은 절대 섞이지 않습니다.**

예전에 브랜드 색과 "안전" 등급 색이 똑같은 초록이었습니다. 그래서 실행 버튼이
초록이라는 이유만으로 "안전해 보이는" 착시가 생겼고, 실제 위험도와 의미가 뒤섞였습니다.
지금은 분리돼 있습니다:

- 파랑 = 조작 가능한 UI(버튼, 선택된 칩, 링크, 포커스). 의미 없음, 브랜드일 뿐.
- 초록~빨강 = 위험도 5단계. **오직 진단 결과에만** 씁니다.
- 앰버는 "주의/추천" 신호로도 씁니다(경고 배너, 추천 카드 배지).

위험 5단계는 점수 구간과 문구가 이미 고정돼 있습니다:
  0-20  green  정상 업무 범위 / 그대로 진행해도 좋습니다
  21-40 lime   경미한 압박 / 가볍게 확인만 하세요
  41-60 amber  조건 확인 필요 / 범위와 기한을 먼저 확정하세요
  61-80 orange 방어 필요 / 수락 전 조건을 서면화하세요
  81-100 red   즉각 승인 금지 / 즉답하지 말고 조건부로 회신하세요

## 만들어 주세요 (아트보드)

1. **파운데이션** — 컬러 토큰(브랜드/표면/텍스트/위험 5단계를 시각적으로 분리 배치),
   타입 스케일, 라운드 3단계, 간격 스케일. 각 토큰에 "언제 쓰는지" 한 줄씩.

2. **입력 컴포넌트** — 선택 칩(기본/호버/선택/포커스), 상황 카드(기본/선택/추천 배지),
   텍스트 영역(기본/포커스/글자수 경고), 보호 배지(방패 아이콘 + "선-마스킹 보호 가동").

3. **진단 결과(X-Ray) 카드** — 이 제품의 핵심 화면입니다.
   등급 점 + 경보 헤더 / 큰 점수 숫자(모노) + 게이지 바 / 진단 설명(좌측 강조선 콜아웃) /
   지표 타일 4개(권력 비대칭·시간적 긴급도·요구 모호성·AI 복붙 냄새) /
   접히는 "판정 근거" 표. **위험 5단계 전부의 상태를 보여 주세요** — 이 카드가
   green 일 때와 red 일 때가 어떻게 달라지는지가 시스템의 시험대입니다.

4. **답장 카드 3종** — 라벨 + 본문 + 글자수 + 복사 버튼(기본/완료 상태).

5. **피드백·경고** — 여러 화자 감지 배너(앰버), 관계 비용 경고(레드),
   모드 안내(MOCK/LIVE), 에러 박스, 대기 상태(방패 아이콘).

6. **오피스 방어 영수증** — 앱과 의도적으로 결이 다릅니다. 크림색 종이(#f6f1e4),
   모노스페이스, 아래쪽 찢긴 가장자리. 공유·캡처용 카드라 앱 UI 규칙을 따르지 않습니다.
   이 예외를 시스템 안에 "의도된 예외"로 문서화해 주세요.

7. **모달 패턴** — 영수증 모달, 기록 모달. 오버레이·패널·닫기·액션 버튼 배치.

8. **반응형 대비** — 데스크톱 1280(좌 입력 / 우 결과 2컬럼, 결과 패널 sticky)과
   모바일 375(1컬럼 스택) 두 폭을 나란히.

## 제약

- 모바일에서 터치 타겟 최소 44px, 입력 필드 폰트 16px 이상(iOS 자동 확대 방지).
- 한글 본문 기준으로 조판해 주세요. 라틴 기준 자간·행간을 그대로 쓰면 한글이 답답해집니다.
- 숫자·점수·시간은 모노스페이스 + tabular-nums.
- 라운드는 역할별로 다르게: 큰 값은 실행 버튼과 결과 카드에만, 반복되는 작은 요소는 작게.

## 하지 말아 주세요

- 장식용 이모지를 섹션 마커로 쓰지 마세요. 상태는 색·모양(점, 스트라이프, 배지)으로
  표현합니다. (카테고리 구분용 이모지는 상황 카드 8종에만 예외로 허용)
- 보라-파랑 그라데이션 히어로, 모든 카드에 동일한 라운드+그림자, 전체 중앙 정렬 —
  전부 피해 주세요. 이 화면은 읽는 문서가 아니라 조작하는 대시보드입니다.
- 위험 등급 색을 브랜드 용도로(버튼·링크 등) 전용하지 마세요. 위 의미 규칙 위반입니다.
```

## 사용 후

캔버스에서 토큰을 조정했다면 `src/styles.css` 의 `:root` 에 반영해야 실제 앱에
적용된다. 두 곳이 갈라지면 이 문서의 목적이 사라진다.
