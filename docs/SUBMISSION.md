## STEP 2 — 배포 (키 필요)

Vercel 팀(`v2sioninmymind-4818s-projects`)을 만들고 `office-firewall` 프로젝트를
GitHub(`v2sion/office-firewall`, production branch `main`)에 연결해 뒀다 — 이제
`main` 에 푸시하면 자동으로 배포된다. **환경변수는 대시보드에서 직접 넣을 것**
(API 키를 채팅 세션에 노출하지 않기 위해 의도적으로 이렇게 함):

1. https://vercel.com/v2sioninmymind-4818s-projects/office-firewall/settings/environment-variables
2. **Production** 환경에 추가:
   - `GROQ_API_KEY` = (본인 키, console.groq.com 에서 발급)
   - `GROQ_MODEL` = `openai/gpt-oss-20b` (라이브 검증 완료. 이 계정에서 실제로
     응답하는 모델은 `openai/gpt-oss-20b` / `120b` 뿐이다 — STEP 3 참고)
3. 저장 후 재배포 트리거 (`main` 에 새 커밋을 푸시하거나, 대시보드에서 Redeploy)

CLI 로 처음부터 하고 싶으면 대안:

```bash
cd office-firewall
npx vercel link --project office-firewall --yes
npx vercel env add GROQ_API_KEY production
npx vercel env add GROQ_MODEL production        # 값: openai/gpt-oss-20b
npx vercel --prod
```

배포 후 확인:

- [x] 페이지가 뜨는가 — https://office-firewall.vercel.app
- [x] 분석 실행 시 모드 배지가 **AI 분석** 인가 — STEP 3 실측에서 5종 모두 `mode: live` 확인
- [ ] `vercel.json` 의 `maxDuration: 25` 가 현재 플랜에서 거부되지 않았는가

## STEP 3 — LIVE 실측 ✅ 완료 (2026-09-18, 커밋 `bd18cb3`)

배포본에서 골든 5종을 실제 Groq 호출로 돌려 **전부 기대 구간 통과**를 확인했다.

| 골든 시나리오 | 점수 | 등급 | 기대 구간 | 지연 | 토큰(in/out) |
|---|---|---|---|---|---|
| ① 주말 침범 | 84 | red | 61~100 | 1,250ms | 2,240 / 531 |
| ② AI 슬롭 | 48 | amber | 41~100 | 1,736ms | 2,195 / 863 |
| ③ R&R 핑퐁 | 64 | orange | 41~100 | 2,099ms | 2,185 / 654 |
| ④ 클라이언트 갑질 | 79 | orange | 61~100 | 20,073ms | 2,219 / 648 |
| ⑤ 정상 업무 대조군 | 8 | green | 0~20 | 1,288ms | 2,197 / 689 |

- 사용 모델: `openai/gpt-oss-20b` (Groq 무료 티어)
- 평균 지연: 정상 응답 기준 1.2~2.1초
- 프롬프트 캐싱: Groq 미지원이라 `cache_read_input_tokens` 는 항상 0 (정상)

**심사 기간에 주의할 것 — 처리량 상한:**
무료 티어는 **8,000 TPM** 이고 호출당 약 2,500~2,900 토큰이 나간다. 즉
**서비스 전체가 분당 약 3건**이 상한이다. ④ 의 20초는 429 직후 SDK 자동
재시도가 TPM 창을 기다린 값으로, `maxDuration` 25초에 아슬아슬했다.

- 한도를 넘으면 429 → 클라이언트가 로컬 룰엔진으로 폴백하고 배지가 `오프라인 분석`
  으로 바뀐다. 화면이 비지는 않으므로 심사 중 치명적이지는 않다.
- 심사위원이 몰릴 것 같으면 console.groq.com 에서 Dev Tier 로 올리거나,
  시연 직전에는 연속 실행을 피할 것.

> **시연 안전장치**: 모델 호출이 실패해도 화면은 비지 않는다. 로컬 룰엔진으로
